# 跃迁计划 · 教练交付作战台

覆盖“线上前 10 天 → 线下 5 天 → 线上后 10 天”的内部交付协同站。项目方配置营期、教练与学员；教练登记本组进度、验收证据和异常；所有权限在服务端校验。

## 接手开发

```bash
npm install
npm test
npm run dev
```

核心代码：

- `app/operations-app.tsx`：业务界面。
- `app/api/workspace/route.ts`：服务端接口与权限校验。
- `app/chatgpt-auth.ts`：Sites 登录身份读取。
- `db/schema.ts`、`drizzle/`：D1 数据结构与迁移。
- `lib/policy.mjs`：分组权限和验收证据校验。

## 用新的 GPT 账号重新部署

1. 克隆本仓库，在 Codex 中打开项目。
2. 安装或启用 Sites，要求它“读取 README，创建一个新的 Sites 项目并部署当前代码”。
3. 将 Sites 运行变量 `INITIAL_OWNER_EMAIL` 设置为新负责人的 ChatGPT 登录邮箱。
4. 保持站点为公开访问，业务数据仍由应用内成员邮箱和小组权限控制。
5. 用负责人账号首次进入，创建真实营期，再录入教练、分组和学员。

`.openai/hosting.json` 已移除原站点的 `project_id`。新账号首次部署时必须创建自己的 Sites 项目，不要填回原项目 ID。

## 数据边界

- GitHub 仓库只包含代码和空数据库迁移，不包含原站点的学员、教练、进度、证据或异常数据。
- 新部署会创建新的 D1 数据库；原站点数据不会自动迁移。
- 不要把原站点数据库、登录凭据、部署令牌或本地 `.env` 提交到 GitHub。

## 权限规则

- `owner`：查看和修改全部项目数据。
- `coach`：只能查看和修改自己负责的小组。
- 未登记邮箱：不能读取项目数据。
- “已通过”必须提供 HTTPS 证据链接或文字验收记录。

## 当前产品边界

暂不包含学员端、文件上传、站内聊天、消息通知、飞书自动同步、绩效管理和多期营复用后台。
